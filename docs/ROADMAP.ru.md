# Filamentra — дорожная карта

[English](ROADMAP.md)

> Плановый документ. Указанные этапы — цели, а не обещания или завершённые функции.

## Основные принципы

- **Сначала визуальный внешний вид.** Filamentra — каталог внешних видов филаментов, а не база механических свойств.
- **Установка по запросу.** Каталог находится вне модели Fusion; в активной модели создаются только выбранные внешние виды.
- **Без повторных установок.** Записи каталога определяются по стабильным ID, а не только по изменяемым отображаемым названиям.
- **Не перекрашивать автоматически.** Установка внешнего вида не должна изменять геометрию или применять отделку без явного действия.
- **Проверяемые данные каталога.** Записывайте источники и чётко различайте цвета производителя и приближения.
- **Проверка в реальном Fusion.** Автономные модульные тесты необходимы, но недостаточны для утверждений о совместимости API.

## Этап 0 — осуществимость API

- Подтвердить поддерживаемые методы создания и изменения Appearance по актуальной официальной документации Fusion API.
- Подтвердить, какие атрибуты и идентификаторы могут сохраняться в Appearance или Design.
- Подготовить прототип моста HTML Palette ↔ Python и жизненного цикла его событий.
- Зафиксировать результаты и ограничения совместимости API.

**Критерий завершения:** один чётко определённый и документированный способ создать и определить визуальный внешний вид в активной модели Fusion.

## Этап 1 — Palette и Install

- Минимальная палитра с небольшим встроенным тестовым каталогом.
- Установка одного визуального Appearance в текущую модель без его применения.
- Обнаружение уже установленного ID каталога.
- Проверка сохранения и повторного открытия, нескольких попыток установки и переключения документов.
- Явное различие состояний ожидания, ошибки и установки.

**Приёмка Fusion:** создание и сохранность внешнего вида, правильный цвет, отсутствие дубликатов.

## Этап 2 — модель данных и просмотр каталога

- Версионированная JSON-схема производителя, серии, цветов, отделки, источников и стабильных ID.
- Просмотр и поиск записей каталога.
- Локальная проверка дубликатов ID, неверных цветов, несогласованных источников и путей.
- Первоначальное заполнение небольшой проверенной по источникам подборкой реальных филаментов.

**Критерий завершения:** проверка каталога работает без Autodesk.

## Этап 3 — применение внешнего вида

- Явное действие Apply to Selection для поддерживаемой геометрии Fusion.
- Список установленных материалов для активной модели.
- Безопасное удаление неиспользуемых внешних видов, когда Fusion это допускает.
- Сохранение ID каталога и отпечатков содержимого для надёжного сопоставления.

**Приёмка Fusion:** меняется только выбранная геометрия; повторные операции не создают дубликаты.

## Этап 4 — распространение через GitHub и автономный кеш

- Версионированный каталог на GitHub.
- Локальный кеш с автономным резервным режимом.
- Проверка обновлений и обработка ошибок без прерывания моделирования.
- Отсутствие незаметных изменений внешнего вида, уже используемого в сохранённых моделях.

## Этап 5 — точность поверхности и расширение каталога

- Проверка профилей отделки: матовой, глянцевой, silk, полупрозрачной и композитной.
- Добавление текстур только после проверки поведения официального Fusion API.
- Расширение каталога по производителям, сериям и официальным цветовым вариантам.
- Проверка поддерживаемых конфигураций macOS и Windows.

## Пока не входит в область проекта

- Запись и изменение файлов Autodesk `.adsklib`.
- Сертифицированные данные плотности, механических свойств или наборы FEA/CAE.
- Гарантированная колориметрическая точность относительно напечатанного объекта.
- Среда выполнения Inventor, обратная разработка проприетарного формата библиотек Autodesk или отдельный сборщик ADSKLIB.
- Незаметная замена внешних видов, изменённых пользователем.

## Результаты приёмки

Для каждого этапа, зависящего от Fusion, фиксируйте:

- Версию Fusion и операционную систему.
- Точный проверенный образец каталога.
- Что выполнено вручную, а что автоматически.
- Фактические результаты, ошибки и, где полезно, скриншоты.
- Оставшиеся риски совместимости.

Не отмечайте этап Fusion как пройденный без выполнения его проверок в Fusion.
